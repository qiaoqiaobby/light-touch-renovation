## 六个方案

同一条诊断：上一任住户的餐桌占着沙发和电视之间的中轴，约 8.9 m 的长厅既不像客厅，也不像餐厅。活动家具属于上一任住户，诊断只把地面、墙面、吊顶、门窗、固定柜体、空调位和插座当作约束。

| 方案 | 它怎么处理这块地面 | 文档所标层级 |
| --- | --- | --- |
| 一「减」 | 轴线留着。电视拿掉，西墙改投影和拉下幕布。折叠桌平时贴东墙收成一块薄板。分区靠地毯和灯光。 | 最高 L2 |
| 二「分」 | 东墙伸出一组双面书架，沙发转向靠窗。长厅分成窗前、起居、用餐三段。 | 最高 L3 |
| 三「空」 | 不用大沙发，改矮榻。中段地面铺席，留给运动。西墙涂层直接当投影面。 | 最高 L3 |
| 四「墙」 | 功能收进东墙 600 mm 的厚度。书桌、坐榻龛、双折餐桌、椅仓排在同一面无把手立面上。收起时地面空着。 | L3 |
| 五「台」 | 北半厅抬成 450 mm 地台，和飘窗连成一片。桌板平时就是坑盖，升起后变成餐桌。 | L3 |
| 六「动」 | 一座带锁定脚轮的体块停在两个预埋定位座上。它停在哪，餐区就有多大。 | 定位座与吸顶投影线槽为 L2；体块本身是独立家具 |

方案五「与飘窗齐平」依赖飘窗台高 450 mm 这个假设。六份方案都还没有按优先级公式排序：公式要等业主把 10 点分给六个维度之后才能算。

建议的推进方式写在两份说明的结论里。页面一只比较，不代替业主选择。倾向方案四或六时，说明里要求先用成品翻板桌和带锁定脚轮的独立书架试用两周。

## 推导顺序

`promept.md` 把流程定成七步。前三步只认识人和房子。

0. 需求画像。每位成员 10 点，分给光线、环境舒适、布局动线、空间尺度、材质色彩、收纳秩序。
1. 保留清单与约束。先写不能动什么，再谈设计。预算和预计居住年限属于这一步，目前待确认。
2. 一周观察。看东西堆在哪、人从哪绕。
3. 现场诊断。按清单给现状打分。
4. 加权排序。`优先级 = (5 − 现状评分) × 维度权重 ÷ 投入系数` 。同分时，层级更低的排前面。
5. 阶梯式实施。先做排在前面的 L0–L1，试用一两周。问题还在，再升到 L2 及以上。
6. 回访。对照原来最不满意的三件事。

| 层级 | 动什么 | 可逆性 |
| --- | --- | --- |
| L0 | 清理、重摆、改变用法 | 完全可逆 |
| L1 | 灯、窗帘、地毯、活动家具 | 完全可逆 |
| L2 | 刷漆、贴膜、换五金和面板 | 部分可逆 |
| L3 | 定制柜、轻质隔断、改门 | 较难逆转 |
| L4 | 拆墙、开洞、拆吊顶、移动水电 | 基本不可逆 |

L4 在本项目里只作为「需专业人员评估」的选项出现。要确认是否承重、管线走向，并遵守物业规定。

## 校验与重新打包

需要 Node.js。依赖只有构建用的 `three` 和 `esbuild` ，装在开发依赖里。

```powershell
npm install
npm run validate
npm run mutate
npm run lint:tokens
```

`npm run validate` 同时检查两个页面：物体是否在房间内、落地家具是否重叠、主路线净宽是否不小于 800 mm、运动区是否放得下垫、聚会是否不少于 6 座、双人餐是否不少于 2 座。创意页还会检查机构姿态。

`npm run mutate` 故意写进已知的违规，确认对应检查会抓住它。

`npm run lint:tokens` 检查界面有没有写出 token 之外的视觉数值。

截图走本机 Chrome 的无头模式，默认软件渲染。成品路径要传给脚本。输出在 `mid/shots/` ，不入库。

```powershell
node viz/scripts/shots.mjs docs/plan/客厅微改三方案-202609301526.html basic
node viz/scripts/shots.mjs docs/plan/客厅创意三方案-202609301615.html creative
```

Chrome 不在默认路径时设置环境变量 `CHROME` 。要看本机显卡下的帧耗时和环境光遮蔽，加上 `GPU=1` 。

重新打包会把 Three.js 和样式内联进一个新的 HTML，写到 `docs/plan/` 。时间戳自己指定，避免覆盖已交付的文件。

```powershell
node viz/scripts/build.mjs 202610081530 basic
node viz/scripts/build.mjs 202610081530 creative
```

脚本结束时会打印成品体积，以及文本里出现的外部 URL。运行页面不需要这些 URL。交付前看一眼打印结果。

最近一次记录见 `ROADMAP.md` 的「最近验证」。那次是 2026-10-01：校验 798 项全部通过，变异 31 项全部被抓住，token 检查 16 项全部通过。页面一截图 56 张、页面二截图 125 张，控制台报错都是 0，最小字号 12 px。以后以路线图里更新的数字为准。
