# 客厅三方案并入复尺 · 对抗审查

2026-10-12。两份旧页面并进当前户型三维：尺寸以 `docs/plan/户型净尺寸核算-202610121252.html` 为准，三套客厅方案的家具尺寸和用途来自 `docs/plan/客厅微改三方案-202609301526.html`。摆放写在 `src/floorplan/living-schemes.ts`，检查是 `npm run audit:plan` 的后半段。

## 结论

方案页的家具不能按原坐标搬进复尺模型。核算给出的客厅主体是 3364 × 5738 mm（x 5542–8906，y 6252–11990），方案页按 3600 mm 开间、约 8.9 m 总进深来摆。直接平移后，靠东墙的沙发、书架和收纳墙会穿出 8906 这道墙，靠南的收纳还会越过 y=11990 的东墙折线。

三套方案已按实墙重摆，家具外形尺寸不缩放。15 个「方案 × 使用状态」全部通过检查。仍有三处方案页的句子在这张净尺寸图上不成立，模型里改了，旧 HTML 没有改：

- 方案一的 90 寸幕布和 2.6 m 观看距离，改成 65 寸、坐面前沿到幕布 2372 mm。
- 方案二「西侧通道约 1.8 m」，实为 964 mm。沙发到吊装幕布 1560 mm，不是原来的约 1.9 m。
- 方案三的约 80 寸墙面投影，改成约 55 寸，矮榻前沿到墙面 2430 mm。

`viz/` 里的方案页和它的 970 项校验仍用 14 mm/px 的旧壳。那一页没有重写。两套图现在会给出不同的开间，以核算页和户型三维为准。

## 审查怎么做的

证伪对象是「把方案页的坐标原样放进复尺轮廓，尺寸承诺仍然成立」。检查不看效果，只看这几件事：

- 每件家具的中心和四角都在客厅多边形内。
- 落地实体互不重叠。地毯可以压在别的东西下面。
- 冰箱和收纳墙的门前净空在房间内，且没有被别的落地家具占用。
- 一个 800 mm 见方的人能从入户走到厨房门、卫生间门和北侧过道。瑜伽垫在运动状态里算占用。
- 运动区里存在 2000 × 1000 的空地，瑜伽垫在这个区里。
- 双人餐至少 2 座，聚会至少 6 座。
- 方案一观看距离落在 2000–2600 mm，方案二西侧通道落在 800–1200 mm，方案二幕布距离落在 1400–1800 mm。这三道是为了防止摆放被改回方案页的旧句子。

空跑防护：在方案一的日常状态里加一块放在东墙外的方块，检查必须报「不在房间内」。这一项已捕获。

## 检查结果

`npm run audit:plan`：户型轮廓部分与并入前相同，失败 0。三方案 15 个状态全部通过。打印的三处尺寸是观看距离 2372 mm、西侧通道 964 mm、幕布距离 1560 mm、方案三投影距离 2430 mm。变异 1 项被捕获。

`npm run typecheck` 通过。浏览器里切过示意、减、分、空，以及观影和俯视。控制台无报错，有一条三维库的 `THREE.Clock` 弃用警告。390 宽没有横向溢出。新按钮字号不小于 12 px。

## 没有做的事

没有改 `docs/plan/客厅微改三方案-202609301526.html`，也没有改 `viz/`。那一页的校验按旧壳编写，改坐标会拆掉 970 项检查的前提。离线方案页仍然能打开，但它的开间不要再当成复尺结果。

没有把层高 2.70 m、窗台高度、吊顶能否挂幕布、玄关有没有冰箱插座写成已确认。这些仍是假定或待确认。平开门洞宽仍不宜直接拿去订门。

没有把三方案延伸到卧室。卧室里的床和柜还是「放得下」的示意，不是方案。
