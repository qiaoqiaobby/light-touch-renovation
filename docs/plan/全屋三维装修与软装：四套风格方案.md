# 全屋三维装修与软装：四套风格方案（实施计划）

## Context

业主要求：把已完成的四套全屋风格方案（素木 S1、木与钢 S2、席地 S3、对照暖古典 S4，数据在 `boards/data/schemes.mjs`）做成 three.js 全屋三维，含硬装（墙、地、顶、柜体、刷漆贴膜、挂墙床头板、收纳墙）和软装（家具、灯具、窗帘、床品、地毯、陈设），覆盖客厅、玄关、卧室 A/B/C、厨房、卫生间七个空间，并做对抗性审查。已确定的选择：

- 交付一个双击就能离线打开的单文件 HTML：`docs/plan/全屋三维装修-<YYYYMMDDHHmm>.html`。代码在户型三维（`src/floorplan/`）基础上扩展，新代码放 `src/decor/`。
- 高保真实时三维：真实家具造型、程序材质纹理、柔和阴影、环境光遮蔽、昼夜分层灯光。页面常驻「模型示意，非效果图」。
- 每套方案可逐级查看：L0 现状清空 → L1 软装 → L2 表面（刷漆、贴膜、换灯、挂墙件）→ L3 定制柜。
- 布局一律沿用已通过检查的数据：客厅取 `src/floorplan/living-schemes.ts` 的 s1/s2/s3，卧室与厨卫取 `boards/data/schemes.mjs` 各房间的 `pieces` 与 `boards/data/house.mjs` 的 `FIXED`。三维不改任何坐标，四套方案的差别只在硬装和软装。

完成标志：四套 × 四阶段 × 八个固定视点 × 昼夜都能在单文件里切换；`npm run decor:audit -- --mutate` 失败 0、变异全部捕获；截图检查通过；对抗审查文档写完，其中「高」级问题全部处理。现有的 `audit:plan`、`board:check`、`typecheck`、`build:plan` 保持通过。

## Approach

**`src/decor/retained.ts`**：现状颜色与白平衡

- 写死 VR 取样色（来源注释：`mid/jalo/crops/crops.json` 各 `base-*` 的 `palette[0]`，2026-10-15 取样）：`tile #a1a49d`、`wall #f1fefe`、`ceiling #fffffd`、`blue #7da7c7`、`redwood #6d3824`、`cabwhite #fbfbfb`、`kitblue #488bb7`、`bedfloor #b5b0a1`。
- `export function whiteBalance(hex: string): string`：sRGB 转线性；以 `wall` 的线性三通道均值为目标，算三通道增益 `g_c = mean / wall_c`；把增益乘到输入色上，限制在 0–1，再转回 sRGB 十六进制。
- `export const RETAINED_HEX: Record<string, string>`：上述 8 项校正后的值。
- `export const EXISTING: Record<string, MatSpec>`，未取样的现状材料都标 `neutralExempt: true`：
  - `tile`（`RETAINED_HEX.tile`，粗糙度 0.2，纹理 `tile` 800，accent 在原色上减 6% 亮度）
  - `wall`（粗糙度 0.92）、`ceiling`（0.95）
  - `blue`（0.6，纹理 `stripe` 120，表示护墙板竖线）
  - `redwood`（0.5，`wood` 900）、`cabwhite`（0.45）、`kitblue`（0.3）
  - `bedfloor`（0.6，`planks` 1200）
  - `wetTile #cfd0cd`（0.3，`tile` 300）、`wallCeramic #e9e9e6`（0.25，`ceramic` 600）
  - `counterStone #8f8a82`（0.35）、`doorWhite #efeee9`、`doorEntry #5a3424`、`sillStone #e9e7e2`（0.35）
  - `appliance #f4f4f2`（0.35）、`steel #b9bcbe`（金属度 0.7，粗糙度 0.35）、`ceramicWhite #f3f3f1`（0.15）

## Assumptions & contingencies

- 卧室 A 床垫用 1800 × 1950。业主坚持 2000 长床垫时，床尾通道只剩约 477 mm：把审查第 J 项的上限改为 2025，并在审查文档里写明「低于 500 通行要求」。
- 白天只做阴天天光，不模拟直射阳光；业主确认真北方向后才另加日照。
- 吊顶按平顶建模；厨卫墙砖按中性白砖；蓝色护墙板做整面墙高、范围由旧方案页换算。现场复核后只需改 `zones.ts`、`retained.ts`、`extras.ts`。
- L0 四套相同，以 s1 布局的冰箱、餐边柜、鞋柜位置代表现状。
- 白平衡校正后，若某项「保留」的硬装与色板色差超过 15，不改方案，只在审查文档列为「保留色复核」，留给业主决定。
- 若无头 Chrome 在 SwiftShader 下拿不到 WebGL：改用 `--use-angle=metal --enable-gpu` 再试一次。仍失败，就在审查文档里写明「浏览器验证受阻」，只交付审查脚本、构建结果和手工打开的确认，不伪造截图结论。
- 若调光后，某方案某视点的亮度仍超出判据区间：不单独为它调光（会破坏可比性），在审查文档里记为该方案的特性（例如 S4 深色材料偏暗），截图判据对该张改为人工确认。
- 若 `@react-three/drei` 的 `RoundedBox` 导入失败：改用 `three/examples/jsm/geometries/RoundedBoxGeometry.js`（`viz/src/creative/main.js` 第 6 行就是这样用的）。
